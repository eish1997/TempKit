## 1. 目标、范围和执行约定

用户反馈“New API 连接”里什么都往里放，要求先梳理再制定完整计划，交给另一个对话统一完成。本文件是本次整理的唯一台账；G 阶段历史交付继续以 generation-plan.md 为准，不重新打开旧阶段。

最终结果：用户从主面板找到设置，在模型连接中只管理连接；从具体预设配置它使用的连接、模型和生成参数；额度及本地文件维护各有独立位置。一次交付完整导航、页面、旧数据兼容、必要自动测试和原生验收，不分批交付半套入口。

最初仅规划；本对话已明确授权实施。授权范围内，普通可逆实现与隔离验证持续推进，不每完成一个切片询问是否继续。没有自动授权付费模型请求、真实令牌轮换、生产迁移、清理用户文件、停止当前测试程序、覆盖正在运行的 exe 或推送新提交。其他对话有明确授权时以其最新指令为准。

不做：重写画板/宿主、引入新前端框架、另建资源/连接/任务体系、账户余额查询、实际账单同步、修改额度规则、模型计价规则编辑器、取消上游请求、增加新模型协议。本轮也不扩展预设名称/指令/封面的完整编辑器；保留现有自定义能力创建功能。

### 3.1 入口与导航

- 主面板工具区新增一个统一图标库的设置按钮，保留现有主题、导入、添加能力、预设库、卡片高度、固定入口及拖动空白区域。不要挤坏 120px 最窄布局；必要时采用与已有工具区一致的溢出方式，先查现有布局。
- 复用现有 manager 附属窗口，设置首页只有三个分区入口及必要摘要，不同时铺开所有表单。
- 预设库删除 New API 连接入口；已添加预设的行增加“模型设置”入口。画板预设卡片提供对应菜单动作，必须与拖放执行、卡片点击及拖动手势分开，不能误触生成。
- 每个子页有真实标题和返回上一级；预设模型页返回其来源。关闭仍关闭附属面板。旧 gateway 模式如保留兼容，应路由到模型连接，不能另留一份旧设置树。
- 本轮预设入口名固定为“模型设置”，避免暗示本次实现了完整预设编辑器。
- 普通预设库/新增能力继续沿用紧凑尺寸；设置页建议约 360×440 逻辑像素，允许依实际布局小幅调整，但必须经工作区边界夹取、邻接定位和滚动适配。页面切换不能突然盖满画板。

### 3.2 模型连接

- 首页优先连接列表，按钮“添加连接”；没有连接时提供简洁空态及添加动作。添加表单按需进入。
- 列表主标识优先使用已有账号名称与服务地址/主机名组合，显示状态。无需为了命名新增 schema；重名时用地址及内部 ID 短后缀区分。内部 ID 在详情中展示，不作主标题。
- 宿主当前返回的连接摘要若缺账号/地址，增加最小只读脱敏 DTO，按现有 profile 关系读取；不得返回明文令牌、加密凭据原文或签名结果 URL。地址展示须去除潜在 userinfo/敏感查询信息。
- 添加连接保持地址、账号名称、令牌、保存语义，账号名称为现有连接身份，不擅自改为任意中文昵称或自动修改已有身份。重复保存不得伪装成更新已有连接。
- 详情包含服务地址、账号、认证状态、检测连接、可用模型、更换令牌、撤销连接。检测只走现有发现接口，绝不自动生图。
- 检测成功主文案“认证通过 · 可见 N 个模型”；完整模型列表可展开，并给长 ID 换行/复制能力。不能把发现成功写为图片生成已验证。
- 可用模型选择优先复用检测结果；没有结果时允许手填准确 ID。持久缓存不是必需项，未检测不能显示空列表为“无模型”；不自动批量探测全部连接。
- 更换令牌独立子页：保留同账号确认、清空密码框、重新验证要求。撤销入口放详情底部，在动作前清楚说明对预设和已发出请求的影响。凭据清除失败时才出现“重试清除凭据”。
- 撤销后显示真实状态并保留历史绑定可检查，不让条目或错误悄悄消失。

### 3.3 预设模型设置

- 通过 presetId 打开具体预设；显示预设名称和“模拟执行 / 已配置真实模型 / 连接不可用”状态，避免“已绑定”等同可调用。连接或模型变化时不得串写另一预设。
- 从卡片进入不再要求用户重新从全局预设下拉中找自己；预设库入口同样传递明确 ID。预设消失时显示错误并停止保存，不误保存到默认项。
- 主要字段：连接、模型；尺寸与质量在“生成参数”中；返回方式放折叠的“高级选项”，默认服务默认值。不编造当前渠道未声明的参数选项。
- 保存、解除绑定继续调用现有宿主命令。保持预设 ID、名称、指令、封面及其他字段，更新不得通过整份旧 abilities 覆盖新数据。
- 解除绑定明确提示“后续使用模拟执行，已有任务与结果保留”；不能静默表现为真实请求。保存不触发模型调用。
- 已有任务保持原连接/模型/参数快照；历史失效绑定依然可查看、改绑或解除。费用未核验及额度不足是独立阻断条件，页内给对应说明/设置跳转，但不复制完整额度表单。
- 与“添加连接”互跳需要保留非敏感草稿和返回来源；未保存草稿返回/关闭需明确放弃或保留策略，至少不能静默丢失。令牌草稿不持久化。

### 3.4 调用额度

- 独立显示总额度、已预留、可用金额；明确是 QuickGen 本地调用限额，不是 New API 余额或实际账单。
- 完全沿用当前一次设置、不能重置/提高、精度校验及费用批准规则。未设置展示输入；已设置以只读数据展示，不放不可用的整张编辑表单。
- 不把历史阶段说明写成新用户必须理解的术语；用实际行为说明“一经设置，当前版本不支持修改”，同时保留宿主真实限制。
- 费用未核验/规则过期不能通过界面调整绕过；本轮不新增费用规则安装 UI。

### 3.5 存储与恢复

- 用三个可进入的区块组织“结果暂存”“拖出副本”“完整恢复副本”，避免一屏排列全部清理按钮。
- 结果暂存：占用、受保护待保存数量、遗留数量；刷新、清理已保存重复副本、备份并移出遗留文件。保留原保护条件。
- 拖出副本：占用、数量、查看目录、清理、备份移出；保留确认复制已完成、批次上限、占用/修改/未完成文件不删除等语义。详细规则在操作确认或次级说明中展示。
- 完整恢复副本复用托盘现有流程。必须由主画板完成待处理工作、场景、便签保存屏障后再导出；manager 不得直接绕过屏障调用 recovery_export。
- 实施时抽取/复用 board.js 已有 recovery-export 处理链，通过宿主发起请求、回传结果/失败，任务关联避免串响应；保留托盘快捷入口。不要新造第二套导出实现。
- 备份并移出不是释放全部磁盘空间；临时副本备份不是完整备份。只在操作附近清晰说明。
- 打开恢复目录仅在真实生成并验证后提供；原有保存错误不能被维护成功提示覆盖。

## 4. 实现边界与状态处理

已知代码：desktop/ui/{board.html,board.js,manager.html,manager.js,manager.css,gateway-settings.js,gateway-rotation.js,image-binding-settings.js,image-budget-settings.js,image-storage-settings.js,icons.js}；desktop/src-tauri/src/{board.rs,resource_commands.rs,storage.rs}，以及实际发现的 gateway/profile 查询实现。不是冻结白名单，必要依赖按范围记录。

- 建立轻量、单一 manager 页面导航与生命周期管理，统一标题、返回、错误呈现和销毁。页面 mount 应能取消展示更新/释放监听；不引入第二个业务状态库。
- 每个读取或保存请求关联当前页面实例及对象 ID；返回、关闭、切换连接、快速重开后，迟到响应不得重建旧 DOM、覆盖新提示或写错对象。
- 界面离开不等于宿主操作取消。发出变更后禁重复提交；重新进入从宿主读取实际状态，网络/IPC 模糊结果不能自动重复撤销、轮换或清理。
- 错误按操作就近呈现；载入、空态、禁用态、保存中、失败可重试均一致。敏感输入退出/成功后清空。长名称、地址、模型 ID、中文、空模型、撤销连接和多个连接均要可用。
- 保持统一图标、主题、圆角、间距及键盘焦点。返回后焦点回到来源控件，菜单关闭恢复焦点；不干扰原生中文输入法。
- Rust 保持资源、连接、持久状态和任务权威。前端仅持有未提交草稿、导航和短期检测展示结果。数据模型原则上不迁移；确需改 schema 必须先说明必要性和兼容方案。
