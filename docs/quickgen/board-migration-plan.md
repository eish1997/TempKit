## 当时的优先级修订（2026-11-13）

用户授权按桌面共存问题收敛。交互原型成熟不代表浮层技术验证完成：B2新增“桌面共存性能”门槛并重新验证，B3保持未完成验收；B4新增功能和真实生成接入暂不推进。历史功能通过记录保留，不要求整套重测。

已确认：正常候选运行时用户报告桌面延迟；退出恢复流畅；软件渲染对照中，画板穿透仍卡、关闭画板流畅。CPU/GDI短采样不足以确定根因，禁用GPU未解决。单全屏WebView兼顾显示与命中是待检验设计，不作为不可变前提，也不预判双窗口必然解决。

收敛步骤：
1. 同一候选、相同图片/位置/显示设置，比较默认、no-hover（不推送宿主光标，保留动态穿透）、fixed-pass（不推送光标，穿透时窗口始终不接收鼠标）。固定穿透实验通过Alt＋·退出，实验中面板鼠标不可用是明确隔离条件，不是产品行为。
2. 如果no-hover改善，定位光标桥/悬浮绘制；如果fixed-pass进一步改善，定位动态穿透/输入切换，优先分离显示和控件职责。若两者仍卡，再做无业务逻辑的静态WebView与原生静态图片浮层对照，决定是否需要替换画板显示层。
3. crop仅为按内容区域裁剪的独立实验，默认关闭，不作为未经证实的正式修复。软件渲染仅为已完成的诊断对照，不设为默认。
4. 固定验收动作：后方同一软件的点击、窗口拖动、滚动，覆盖退出/刘海/穿透/画板操作四种状态；记录候选哈希、实验模式、图片数与用户体验，资源采样作为辅证。不能用单元测试通过代替桌面延迟验收。

既有图片数据、预设、自定义、布局、主题和Alt＋·契约保留。实验不开第二产品、不改持久配置；如果需要窗口拆分，先验证最小显示/输入边界，再接回业务。当前最近发布候选仍为004F883BBB77；后续诊断源码未冒充已发布修复。

## 实施边界

- 目标合同见[交互规格](interaction-spec.md)的画板增量。30%透明度、160ms过渡、32px大纲外延、48px渐隐暂作首版参数。
- 独立二进制quickgen-overlay-probe，独立应用标识，无浏览器模拟桌面背景。
- 画板窗和控制窗分离，画板整窗穿透时常驻面板仍可命中。穿透光标由宿主读取，不依赖WebView pointermove。全局快捷键冲突明确报错，不静默隐藏恢复入口。

正式单屏实现修订：画板、堆叠、大纲和能力面板使用同一WebView以保持跨区域pointer capture；收起画板时用原生区域裁切保留面板/入口，穿透模式由宿主约16ms采样鼠标位置，在可操作面板/入口区域与图片区域间切换原生命中。添加/预设继续为独立窗口。双窗口方案保留在技术probe中，不作为当前产品实现。
- 原生物理坐标减去画板窗口原点后除以DPI，转换为局部逻辑坐标；初期只覆盖一个显示器，不声称多屏全桌面完成。
- Asset保存稳定ID和应用内文件引用；BoardItem保存assetId/坐标；BoardScene保存相机/选择/排列；Task保存输入assetId和能力快照。结果为新Asset，关联source/task。重试不重复成功项。
- Rust任务服务负责状态和文件生命周期，UI不持凭据；Task → 统一AI Gateway → Adapter。迁移用显式模拟执行器，不将CSS效果当真实生成。
- 旧config.json/covers保留。画板用独立版本化存储，原型IndexedDB不自动导入；任务恢复为中断，不自动重发付费调用。
