## 目标与授权

将已迭代的浏览器交互转成可在真实 Windows 桌面使用的验证应用：贴边入口、连续形变、原生图片拖入、用户能力面板及配置恢复。W1 已完成开发及发布宿主启停验证。此前持续执行目标已由用户清除；后续圆角、间距、主题等按单次请求实施。本次仅整理文档，不恢复旧目标，也不开始真实生成开发。

本文件为 Windows 桌面验证阶段 W0–W5 的唯一任务台账。整体文档入口见 [README](README.md)，整体模块边界见 [架构](architecture.md)，后续 G 阶段单独见 [最小生成闭环计划](generation-plan.md)（仅规划、未实施）。交互来源为本次已确认需求、interaction-spec.md 和 design/quickgen-prototype.html；p1-window-drag-validation.md 已归并为按 W1–W5 分组的最终验收矩阵。

W 阶段不包含模型调用、真实生成与结果自动保存、结果回拖 DCC、任务队列、历史、SQLite、账号、云同步、自动更新、多图和跨平台。DCC 外拖只做一次探索记录，不影响桌面核心通过。

- 初始基线只有 docs 与 design；现已有 desktop/ Tauri 工程、固定依赖与构建候选，环境和版本记录见后文。当前目录没有 Git 元数据。
- 原型已实现贴边布局、尺寸调整、两种卡片添加方式、图标拖动切换高度及图片暂存逻辑；这些不是已验证的原生桌面能力。
- 本机浏览器曾加载旧页面；恢复服务后还发现 prefers-reduced-motion 为 true，导致形变被禁用。完整预览使用 ?motion=full；产品默认仍尊重系统设置。

- 预览服务是开发辅助，不是交付的桌面应用。正式验证须记录源码版本、构建标识、实际启动路径和 Windows/WebView2 版本，避免再测试错版本。

## 必须保留的交互

1. 入口可贴顶部或左右侧边，能拖动位置；展开后入口本身变成面板，不留下独立刘海。
2. 默认 280×220、两列，最小宽度 120px 可单列；四边四角调整尺寸，列数自适应；隐藏滚动条但保留滚动。
3. 无应用标题和拖手图标。标题行提供添加、预设库、卡片高度、主题切换图标和收起；空白处可以拖动。
4. 高度图标上下拖动实时切换 32/56/80/112px，不出现菜单；键盘操作保留。
5. 添加与预设库是相邻的独立小面板，按内容区间隔 12px，不居中、不贴屏幕边缘；各自 X 关闭，主面板保留。结果页返回与小面板关闭不是同一语义。
6. UI 使用本地 Lucide 图标、统一黑白灰令牌；无常驻说明、占位提示或悬停提示，保留错误信息、状态与无障碍名称。
7. 拖到入口松手暂存图片，再点击卡片；持续拖至卡片松手直接触发。展开导致卡片移到静止鼠标下方不得误触。
8. 本阶段触发只记录文件与所选能力，不显示虚假的“已保存”，无图点击不得发起任务。

## 技术决策门槛

- 优先 Tauri 2；窗口数量不预设。W2 比较窗口边界、动画连续性、透明区域输入穿透和原生拖入能否共存，保留最小满足方案。
- 不接受用大透明矩形挡住桌面，或仅靠前端裁切模拟原生鼠标穿透。窗口形变可采用外形层与内容层分离，先证明原生行为再细调曲线。
- 如果 W2 无法同时满足动画和输入命中，记录具体失败、尝试和可比较方案，先解决窗口结构，不进入模型或大量业务开发。
- 初始仅本机 Windows 为实测平台；核实 OS 后记录，不能据此声称已兼容所有 Windows 10/11。多显示器/DPI 至少验证当前可用配置；缺设备项标为待验证，不伪造通过。
- 配置优先简单本地文件或合适的 Tauri 存储方案，不引入数据库。按完整写入、异常恢复、字段版本升级需求选择实现。

## 动效专项验收

正常模式和减少动态效果模式分开验收。完整演示只作为显式开发选项，不覆盖用户的系统偏好。

- 正常模式：同一外轮廓持续从入口变化到面板，边框/圆角不突然跳到最终大小；内容不拉伸变形。顶/左/右均可辨认来源。
- 收起回到当前入口位置；连续开关可反向衔接，不闪烁、不重播起点、不出现隐藏按钮拦截输入。
- 拖入展开时可继续移动文件；命中检测与可见卡片一致，不以动画完成为借口丢掉 drop。
- 真实应用录屏或逐帧观察至少覆盖顶部和侧边；只有 CSS 参数正确或语法通过不足以判定完成。

## 验证规则

执行时从实际工程配置确定运行、构建和测试命令；不在工程尚未创建时虚构命令。现有原型可用 node --check design/prototype-extension.js 和 node design/build-prototype.mjs 检查构建，但不替代桌面验证。

文件分类/暂存状态/配置恢复等关键分支做针对性自动验证；布局、窗口置顶、穿透、原生拖放与动效需要实际 Windows 操作证据。故障先保留反例，区分环境失败与产品失败；同一路径两次没有新增信息时换诊断，不反复调参数。

每个任务完成后在本文件更新状态与证据。done 要求该切片验收通过；缺真实操作或最终体验确认标 verifying/待验收。W5 未过，不宣称桌面阶段完成。WebP 和 DCC 依旧单独记录兼容缺口，不用它们掩盖 PNG/JPG 必须通过的门槛。
