# 便签候选保存与恢复

此说明对应已验收的便签集成候选 50989457bdb2；唯一验收台账见 notes-integration-plan.md。交付包不会自动替换日常程序，本轮未运行真实数据迁移。

便签由资源数据库的 notes 表保存，当前 schema 为7。记录含正文、常驻、置顶、桌面几何、显示器、字段版本和软删除状态。空白记录有效；删除不清空正文。显式撤销恢复常驻并立即显示，保留正文、置顶和几何。

正文防抖提交；收起、总览、导出和正常退出会等待保存。失败保留草稿并报告错误。异常终止只能保证已确认提交的数据，未确认输入可能丢失。不要删除数据库或清空 WebView 来尝试解决保存错误。

导出数据库快照和 inventory.json 包含全部便签（含软删除）；manifest.json 记录 schema、noteCount 和文件哈希，最后才写入。缺少 manifest 的目录不能当作完整副本。

恢复演练先核对清单哈希，再复制整份导出；不要直接打开唯一备份。将 metadata.sqlite、blobs 和迁移备份等资源复制到全新隔离目录的 resource-store 下，保留全部导出文件。用同版本候选和显式的 --isolated-data 绝对路径启动。JSON 清单不是直接覆盖数据库的导入器。

升级前保留可核验的数据库和配置副本。旧 exe 不支持 schema7，只换 exe 不能无损回退；回退需用升级前备份，同时另行保留升级后新增内容。当前没有逆向迁移器，也不自动导入浏览器原型 localStorage。

隔离托盘导出、正常退出重启、提交确认后强制终止与副本恢复均已核对。恢复副本反映导出时刻；导出后的修改需再次导出才会进入新副本。双屏 125% / 100% 和断屏找回已由用户实际验证，容量范围与限制见执行计划，不由构建成功推断通过。
