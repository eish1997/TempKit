No Intel/AMD integrated GPU was enumerated. Presence of virtual display

No Computer Use-specific GPU preference was found in HKCU UserGpuPreferences.

Reproduction:
1. Fully exit and restart Codex, with Windows desktop unlocked.
2. Launch the existing local Tauri/WebView2 test application.
3. Discover its native window using cua.listWindows and bind using cua.getApp.
4. Call getAXStateAndScreenshot.

Actual:
- Window discovery succeeds.
- Latest screenshot call fails: FrameArrived timed out: timed out waiting on channel.
- Latest accessibility tree exposes panes but no actionable entry button.
- Application startup and native/frontend channel handshake succeed.
- Earlier attempts exposed full accessibility text but screenshot capture timed out;
  element clicks failed with coordinate input geometry is unavailable.
- Earlier independent blank Notepad control also had capture timeout and native
  input failure, while UIA setValue succeeded. These are historical observations,
  not a new post-restart Notepad retest.

Expected: native window capture and input work without modifying signed helpers.

Already tried: application restart, fresh window binding, prior REPL reset,
independent normal-window control. No community binary patch applied.
The integrated-GPU workaround is not applicable to the currently enumerated GPU set.
